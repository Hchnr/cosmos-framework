## 1. 目标与完成定义

本计划用于在当前 `cosmos-framework` 仓库和当前 H100 节点上，以“不做源码开发、不增加性能优化、不采用多卡或跨节点分布式策略”为约束，跑通以下最小闭环：

1. 建立可复现的 Cosmos3 训练环境。
2. 下载并审计官方示例数据、Wan2.2 VAE 和 Cosmos3 基础 checkpoint。
3. 使用单张 H100 对 Cosmos3-Edge 做 1 个 optimizer step 的 Vision SFT smoke run。
4. 产出可恢复的 DCP checkpoint，将其导出为 Hugging Face safetensors。
5. 分别用基础模型和训练后模型完成单样本离线推理，验证输出文件可读。
6. 保存安装、下载、配置、命令、版本、日志、资源占用和产物清单，形成可以复跑的证据链。

选择 **Cosmos3-Edge**，因为它是仓库支持的 2B 模型，官方提供对应的 Vision SFT recipe；Nano 是 8B，而 Edge 的显存需求更适合作为严格单卡基线。模型规模和 Hugging Face 仓库映射见 `cosmos_framework/inference/args.py:1182`、`cosmos_framework/inference/args.py:1192`，Edge SFT 数据与下载入口见 `docs/training.md:82`。

完成标准不是“进程启动成功”，而是以下条件全部满足：

- 环境导入与 CUDA tensor smoke 通过。
- 官方数据 manifest 和抽样媒体均可读。
- 基础模型生成一个有效图像。
- 训练日志中完成 1 个 optimizer step，loss 有限且没有 traceback、OOM 或 NaN。
- `$RUN_DIR/checkpoints/latest_checkpoint.txt` 指向 `iter_000000001`，DCP 目录完整。
- DCP 成功导出为 HF safetensors，训练后模型再次生成一个有效图像。
- `run_manifest.md`、`commands.log`、阶段日志、版本信息和 artifact 校验清单齐全。

### 2.3 “无分布式策略”的准确含义

训练入口会无条件调用 `torch.distributed.init_process_group`，因此当前代码要求通过 `torchrun --nproc-per-node=1` 提供 world-size=1 的启动环境，见 `cosmos_framework/scripts/train.py:184` 和 `cosmos_framework/utils/distributed.py:35`。这只是单进程 rendezvous/NCCL 初始化，不是多卡训练。

官方 Edge recipe 把 trainer 模式固定为 `"fsdp"`，而 trainer 运行时只接受 `ddp` 或 `fsdp`，见 `examples/toml/sft_config/vision_sft_edge.toml:66` 和 `cosmos_framework/trainer/__init__.py:272`。但是当 `dp_shard=1`、`dp_replicate=1` 时，`dp_enabled=False`，模型不会执行 `fully_shard`；判断逻辑见 `cosmos_framework/utils/generator/parallelism.py:228`，FSDP 的实际调用门见 `cosmos_framework/model/generator/mot/parallelize_unified_mot.py:288`。因此本计划保留 recipe 所需的字符串 `distributed_parallelism="fsdp"`，同时把所有并行 degree 固定为 1，并在 resolved config 和运行日志中验证没有实际 shard/replicate/CP/CFGP。

### 2.4 “无额外优化”的准确含义

严格基线显式设置：

- `model.config.compile.enabled=False`
- `model.config.activation_checkpointing.mode=none`
- `optimizer.fused=False`
- `trainer.grad_accum_iter=1`
- DP shard、DP replicate、CP、CFGP 均为 1

官方 recipe 默认开启 compile、full activation checkpointing 和 fused Adam，见 `examples/toml/sft_config/vision_sft_edge.toml:26`、`examples/toml/sft_config/vision_sft_edge.toml:30`、`examples/toml/sft_config/vision_sft_edge.toml:34`、`examples/toml/sft_config/vision_sft_edge.toml:43`。本计划通过一次性 CLI tail overrides 关闭它们，不改官方 TOML；tail overrides 的优先级高于 TOML，见 `cosmos_framework/scripts/train.py:14`。

保留官方 `bfloat16` 数值配置，因为这是 Edge recipe 的原生训练精度和 checkpoint 计算契约，不作为额外优化引入，见 `examples/toml/sft_config/vision_sft_edge.toml:16`。不额外开启 TF32、量化或低精度 optimizer state。

严格基线如果 OOM 或出现后端不支持，当前执行立即停止并保存日志；不自动打开 activation checkpointing、compile、offload、allocator 参数或多卡。任何约束放宽都需要另起版本计划并获得确认。

  -o "$DEMO_ROOT/checkpoints/dcp/Cosmos3-Edge" \

## 9. 风险、停止条件与后续分支

| 风险 | 当前判断 | 处理方式 |
| --- | --- | --- |
| driver、CUDA 13.2 toolkit 与 cu130 wheel 组合异常 | 版本字符串需要实测 | 以 Gate 1 CUDA kernel smoke 为准；失败即停，不擅自换环境 |
| Edge 严格单卡、无 AC/fused/compile 时 OOM | 有可能 | 保存峰值显存和 traceback；不自动加优化或多卡 |
| 官方 HF 资源 gated 或网络失败 | 可能 | 先完成 license/auth gate；同 revision 断点续传并记录 |
| base snapshot 使用浮动 `main` 不可复现 | 已识别 | 下载前解析并固定 40 位 commit SHA |
| `wm-training` 数据格式不兼容 | 已确认 | v0.0.1 使用官方 BridgeData2；适配另立 v0.0.2 |
| dryrun 与正式 run 目录冲突 | 已在计划中隔离 | 分别使用 `outputs/dryrun` 和 `outputs/train`，不交叉复用 |
| 1-step 输出不能代表训练质量 | 必然 | 只声明工程闭环通过，不声明收敛或质量提升 |
| guardrail 带来额外模型下载和不相关失败 | 可避免 | 两次 smoke 都显式 `--no-guardrails`，在交付中注明 |

需要停止且不得自动绕过的条件：

- 目标 GPU 不空闲或存在不明进程。
- 目标目录越出 `$DEMO_ROOT`、已存在且来源不明，或磁盘空间不足。
- HF token/license 不满足。
- immutable revision 无法解析或下载内容与记录不一致。
- CUDA import/kernel、attention backend、数据解码、base inference 任一前置 gate 失败。
- 严格单卡训练 OOM、NaN、进程崩溃或无法生成 checkpoint。
- 任何修复需要修改源码、启用优化项或改为多卡。
